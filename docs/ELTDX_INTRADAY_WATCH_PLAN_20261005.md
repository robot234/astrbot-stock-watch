## 2. 看谁与列表上限

合并上一晚已存候选、已有影子持仓和用户自选，精确市场/代码去重，上限50。优先级：有影子持仓、用户自选、研究候选按原排名；同一优先级代码排序。超额明确列出未监控列表，不悄悄丢持仓、不自动扩大上限；影子持仓超过50须用户选择，在完整名单确认前不假称覆盖所有持仓。

日初冻结列表版本/来源批次/每股加入原因，用户盘中添加也留变更时刻、只影响以后，不回填已错过提醒。正式名单未许可时研究候选明确标“研究，非正式推荐”，无候选也可只看手动自选/影子持仓。名单不足50不补热门股、不扫全市场。

当日限价、交易阶段/ST/特殊制度等必须有同目标日可信证据；前日上下限不直接当今日上下限。09:15前只加载本地已有资料，不发未获授权的盘前探测；首个交易阶段可以在当天元数据预算内读取至多50股证据，未就绪的对应提醒unknown。库内推导限价明确标derived，只在制度/输入完整且用户认可该提醒用途后使用，不当正式来源验收。

| 13:00—15:00 | 每30秒，左闭右开240轮 | 连续阶段小名单 |
| 15:05 | 只读本地日志 | 收盘汇总，不拉全市场或补当日行情 |

总500轮；以已实测20股为保守分批上限，50股最多3批，则快照<=1500条应用请求。交易阶段每60秒一次服务器日期/健康证据<=250条；当日名单/限价/状态元数据实际消息预算<=300条，只针对名单，不调用全市场ST/停牌helper。预计<=2050，全天**2500条实际协议/连接尝试硬停**，余450含连接、诊断及异常开销。身份/状态若不能小名单取，不临时全市场扫描，相关提醒停用。

每条请求超时5秒、无自动重试，不同时跑重叠轮次；一轮最多25秒，错过下一轮就记missed_cycle，不并发追赶。每次真实发包/重连/失败都计数，SDK helper内部多请求也计，不把循环或50股当一次请求。实际批容量、发送计数、耗时若不能支持预算，方案需另版补充，不能直接上线。2500是客户端保护提议，不是供应商官方限额。

午休、09:25—09:30、15:00后/非交易日不轮询，不把不开放时段当断线。竞价报价/撤单语义未实测，不发打开涨停板、成交量、止盈止损判断；竞价只在对应接口及时间证明合格后展示指示价/阶段说明，未合格则只显示未验证。

## 4. 时间、缓存、stale与质量门

每条保留source、server、raw_source_time、source_date、time_basis、日期是否推定、received_at（北京时间/UTC）、monotonic receipt、request_id/run/list版本、cache/expired状态、尝试次数、原始哈希类型和解析状态；先记录原字段，不能为画图捏日期。

- 连续阶段提议源行情年龄>45秒为stale，集合竞价合格指示行情也采用45秒；源时间比接收时间超前>2秒记clock_unknown，回退/日期不符/非法时间或缓存过期unknown。15:00停止后不继续发stale警报。
- 同一源时间+相同数据的重复返回不刷新“最后源更新”；received_at虽变不代表行情更新。没有可核实源日期、源时间只时分秒、仅心跳日期拼接时记 `time_basis=server_date_assumed`，本版不能据它通过新鲜度门、不能发价格方向判断。不能简单拿“电脑今天日期”拼出实时行情。
- 单股完整日期或经独立核实并获用户确认的源日期语义、主机校时证据/允许偏差、同日累积字段重置语义到齐才讨论启用。后续20股盘中测试若只验证心跳日期且仍单股日期假设，报告其延迟为推定值，不能填成实时已通过。
- 不活跃股票久无成交可能真没更新；仍标stale并抑制价格判断，不假称断网。心跳成功但某股过期，是“该股行情过期”；连接失败/服务器日期异常才全局中断。
- 质量失败时只发有冷却的“数据中断/行情过期，不能判断涨跌”，不发“没有异常”，不补漏过事件。报价字段、元数据、成交量及停牌状态可以分别有效，但每种提醒依赖的质量门全部通过才能判断。

源状态更新时刻与最后成交时刻分开。停牌期间没有新成交不能据此推出停牌；停牌/复牌提醒必须是有自己当日新鲜时点、独立语义已确认的状态变化，不用旧成交时间冒充状态更新时间。

## 5. 提醒定义（提议，不回流研究）

| 提醒 | 确切条件及限制 |
|---|---|
| 接近涨停 | 已证同日上限U、当前价p<U，(U-p)/U<=0.5%；触及单列，不以涨跌幅猜上限 |
| 接近跌停 | 已证同日下限L、p>L，(p-L)/L<=0.5% |
| 触及涨/跌停 | 当日上下限合法、价格按分相等；越界为数据异常，不以容差吞掉 |
| 打开涨停板 | 连续竞价、同源连续有效前态已触及上限，后来价至少低1分钱；断线/stale/午休/切源后重建前态，不从未知推开板 |
| 盘中停牌/复牌 | 当日有效源状态从明确交易→明确临停/停牌或反向变化；0x20完整语义/更新时间未确认前不启用；名单缺席不是复牌 |
| 影子止损/止盈 | 读取既有冻结持仓线及规则版本，用新鲜同口径价穿越明确价格线；没有既定线或公司行动后尺度不明则unknown，不新设百分比 |
| 放量异常 | 连续阶段下述采样增量与历史采样基准比，不用未来全日量，不称交易所精确分钟线 |

价格边界提醒基于一次新鲜有效采样，说明采样可能漏掉短时开板/触板、提醒不是成交。影子穿线只告知达到价格，不记买卖或退出收益；缺持仓单位/股份/线版本时停用该项。

### 放量基准固定提议

用可证明当日累计成交量，连续采样构造约60秒增量：同代码/同源/同交易日，两个源时间相距45—75秒，累计量不回退，均新鲜且无missed_cycle；标准化增量率为 `(V_now-V_previous)*60/源时间差秒`，名称“60秒采样量率”，不是精确1分钟成交量。

当前完整采样窗口量率>=之前10个完整合格窗口量率中位数的3倍且增量>0才提醒。过去10窗不含当前窗，至少5个正量窗、中位数>0；不足则volume_unknown，0基准不除、不补0。停复牌/午休/竞价/切源/断线或累计量回退重建窗口；不跨阶段凑10窗，因此每个连续时段开始后先积累，不立刻出放量信号。

累计量单位/日重置/时间语义须安装证据证明，字段不存在或只有盘口挂单量则该提醒不启用。没有调用过去全市场分钟数据或BaoStock，用的只是此前保存的小名单采样，不回流MACD训练或调权重。

## 6. 冷却、通知与留痕

去重键为目标日/代码/提醒类型/规则版本。价格边界/开板/止盈止损冷却10分钟；同一持续条件不反复通知，必须退出条件再重新进入才算新事件。接近→触及是不同类型各可一次，不把两个事件同时刷成多条。

停复牌10分钟且状态相同不重发；全局中断冷却15分钟，每股过期同类15分钟，同批优先一条摘要不50条刷屏。恢复需连续2轮新鲜完整证据才发一次恢复，重建前态，不补发停线期间涨跌。全天最多100条推送，超过后只留日志/收盘汇总，不丢原始事件；不默默屏蔽数据中断状态。

未来独立目录建议 `/home/pi/apps/stock-watch-eltdx-watch-v1`；日志 `logs/watch-YYYY-MM-DD.jsonl`，events/quotes按日/唯一run分开，日末manifest与哈希。记录触发价/边界/冻结持仓线、规则版本、源时间/接收时间、质量判定、冷却抑制、发送结果。行情与提醒不提交GitHub、不冒充真实交易记录。

15:05按本地已有记录汇总：覆盖股票/时段、有效/过期/失败、实际请求/停止原因、各类事件/推送/抑制/失败、未监控/未知及数据空档。未覆盖整时段时汇总写partial，不叫全天无异常；通知失败不靠无限重试刷屏。

## 7. 断线、备用与停止

**初版选择停止判断，不自动切备用源。** 单批失败标该批股票中断；两个连续连接/协议失败或日期/时钟全局异常停止行情判断，记录disconnect，不当作没有异常。底层不允许不计数的自动重连/重试；不能关闭或审计则不启用。默认同日不自动重启，用户明确恢复后检查预算、留新run身份，前态/量基准重建。

腾讯目前只有非交易20/20预检，等待原任务盘中同股时点/价格/时间比较；stock-sdk、新浪未测。未来如采用备用，必须另版明确适用提醒、单位/股票日期/缓存/延迟/限制语义、切源时刻和冷却，先获用户确认；备用不合格就维持停止，不偷偷拿旧/缓存价格续命。

未来仅新增watch任务自己的STOP/停止方式，不操作现有采集或容器；确切单元/停止命令实施授权时再给。2500请求、运行窗口、超时、数据质量、磁盘/日志失败到限分别记原因；原始证据写入失败时停止，不发无法追溯的判断。
